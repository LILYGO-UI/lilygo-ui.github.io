# Serial 串口工具使用说明

Serial 用于调试运行设备上实际连接的串口，程序名为 `lilygo-ui-serial`。
桌面模拟器也使用真实主机串口，通信不需要联网。

## 使用前准备

- 接好串口设备或 USB 转串口适配器，确保操作系统驱动创建了设备节点。
- 按目标设备要求核对电平、共地和收发接线。
- 运行应用的账户需要串口节点读写权限；关闭其他串口监视器。
- 从设备说明中取得波特率、数据位、校验、停止位和流控设置。

## 建立连接

1. 在 Launcher 打开 **Serial**，点击顶部 **Settings**。
2. 点击 **Scan**，在 **Connection** 选择设备节点。
3. 配置串口参数，默认是 **115200 / 8N1 / no flow control**。
4. 点击 **Connect**，确认状态变为 **Connected**。
5. 点击 **Back** 返回接收和发送界面。
6. 更改串口或参数前，回到 Settings 点击 **Disconnect**。

进出 Settings 不会中断连接，接收历史和未发送草稿会保留。
热插拔和断线重连需要手动 Scan / Connect。

## 接收数据

- **ASCII / HEX**：只改变接收显示方式，不改变已收到的原始字节。
- **Time**：为接收块显示本地时间戳，默认开启。
- **Auto**：自动滚动到最新数据；查看旧内容时可以关闭。
- **Clear**：清除历史并重置 RX/TX 计数，连接和待发送队列仍保留。

Receive 只显示收到的数据，发送内容不会自动回显。
ASCII 中非 ASCII 字节显示为转义值，不会自动解码成中文 UTF-8。
每条记录按系统读取块划分，不保证对应一条协议消息。

## 发送数据

1. 在发送区选择自己的 **ASCII** 或 **HEX** 格式，它与接收显示格式独立。
2. 输入内容，例如 ASCII `AT`，或 HEX `41 54`。
3. 按设备协议选择 `No ending`、`LF`、`CR` 或 `CRLF`。
4. 点击 **Send**，查看反馈和 TX 计数，并等待设备实际响应。

ASCII `AT` 加 CRLF 会发送 `41 54 0D 0A`。
HEX 必须是完整字节对，接受 `0041ff` 或 `00 41 FF`，不接受 `0x` 前缀或逗号。
ASCII 不解释 `\r` 字符串；发送控制字节请使用行尾选项或 HEX。
若 HEX 已含结束符，选择 `No ending`，避免重复追加。
TX 增加仅表示系统接受了字节，不证明对端已经处理或确认。

拖动收发区之间的分隔线可调整空间，横屏为左右分栏。
点击输入框会显示软键盘；**Hide keyboard** 关闭后恢复空间，输入仍保留。

## 线路控制

进入 **Settings → Line control** 操作 RTS、DTR 和 BREAK。
需要活动连接且驱动支持；RTS/CTS 流控启用时手动 RTS 不可用。
BREAK 是持续状态，需关闭开关或断开连接结束，不是自动定时脉冲。

## 数据与权限

日志、设置和输入不跨应用重启保存，没有日志导出或定时发送功能。
原始历史最多 256 KiB / 512 条，显示文本最多 32 KiB；这是实时控制台而非完整录制器。
断开会丢弃尚未写出的队列；Clear 不会清空设备驱动缓冲区。
Linux 常见节点是 `/dev/ttyUSB*`、`/dev/ttyACM*`，macOS 使用 `/dev/cu.*`。
选择器刻意隐藏 `/dev/ttyS0` 和 `/dev/serial0`，没有自定义路径输入框。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 无串口 | 检查连接、驱动、节点命名，再点击 Scan。 |
| Permission denied | 检查节点所属组和运行账户权限，按系统策略授权后重新登录。 |
| 已连接但乱码 | 核对两端参数、接线及 ASCII/HEX 显示。 |
| TX 增加但没有 RX | 应用不做本地回显；确认对端是否应该响应。 |
| Line control 失败 | 核对适配器/驱动能力，数据通信与控制线支持是不同功能。 |

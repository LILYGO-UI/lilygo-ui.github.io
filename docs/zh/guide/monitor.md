# System Monitor 系统监控使用说明

System Monitor 是设备本机的运行状态看板，每秒更新一次。
安装后的程序名为 `lilygo-ui-monitor`。

## 使用前准备

- 应用主要读取 Linux 的 `/proc`、`/sys` 和系统信息文件。
- 不需要额外监控服务，也不需要互联网连接。
- CPU 温度需要内核提供 thermal 节点；没有传感器时不能生成真实温度。
- 网络流量来自本机网卡计数器，不是测速服务器的带宽测试。

## 查看总览

1. 在 Launcher 打开 **System Monitor**。
2. 等待几个刷新周期，让 CPU 和网络速率形成有效采样。
3. 查看 CPU、Memory、Storage、Temperature 卡片。
4. 向下滚动查看网卡信息、系统版本、主机名和运行时间。
5. 横竖屏切换时布局自动调整，不需要选择显示模式。

| 项目 | 如何理解 |
| --- | --- |
| CPU | 使用率、在线核心数及 1 分钟负载。 |
| Memory | 已用/总内存与占用比例。 |
| Storage | 根文件系统 `/` 的已用/总空间，不代表所有挂载盘。 |
| Temperature | 内核提供的 CPU 温度及高温状态提示。 |
| 网络接口 | 链路状态、IPv4、实时接收与发送速率。 |
| Uptime | 从系统启动至今的运行时间。 |

网卡动态生成独立卡片，回环和 Docker 相关接口被排除。
没有 IPv4 地址不一定代表接口不存在，应结合链路状态判断。

## 查看趋势

1. 点击 CPU、内存、存储、温度、网络或 Uptime 卡片。
2. 在弹窗查看最近 60 个采样点和当前、最小、平均、最大值。
3. 网络弹窗同时显示 RX 与 TX 曲线。
4. 点击右上角关闭按钮，或点击弹窗外区域，返回总览。

数据从本次启动后逐渐积累，因此刚打开时不一定有完整曲线。
不可用数值显示 `--`，不会以 0 参与统计，曲线保留缺失间隔。

## 数据来源与保存

| 数据 | 系统来源 |
| --- | --- |
| CPU、内存、负载、运行时间 | `/proc/stat`、`/proc/meminfo`、`/proc/loadavg`、`/proc/uptime` |
| 网卡与流量 | `/proc/net`、`/sys/class/net` 及系统网络接口查询 |
| 温度 | `/sys/class/thermal/thermal_zone*/temp` |
| 存储 | 根目录 `/` 的文件系统统计 |
| 系统身份 | `/etc/os-release` 和内核信息 |

趋势只保留当前启动内的最近 60 个样本，没有长期历史数据库或导出入口。
关闭再打开后重新积累；这里不能修改网络设置、清理磁盘或结束进程。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 某项为 `--` | 检查对应系统文件和驱动是否可读；它表示无有效数据，不是零。 |
| 网络速率为零 | 空闲接口可能没有流量；先确认链路，再进行正常网络操作观察变化。 |
| 找不到某网卡 | 检查系统接口是否存在，回环和 Docker 接口不会显示。 |
| 插入 U 盘后 Storage 不变 | Storage 统计根文件系统；另一个挂载点不属于此卡片。 |
| 重启应用后图表变短 | 历史仅在本次运行中保存，等待新采样积累。 |

本文依据本地 Monitor README、系统数据源及统计弹窗实现整理。
